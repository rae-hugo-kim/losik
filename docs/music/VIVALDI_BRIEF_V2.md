## 1. 데이터

- 조성은 `key_name` 이 기준입니다(MIDI `ks` 의 minor 플래그는 신뢰하지 않습니다).
- 박자 변화는 `ts_events`, 피크업은 `pickup` 에 있습니다. `bar_tick(key, bar)` 는 피크업과 박자 변화를 반영한 다운비트 틱을 줍니다.

- 노트가 없는 성부는 빈 리스트입니다(Spring II cello).

## 2. Suno 통과 규칙 (캐논 라운드 실측, MUST)

캐논 v1 은 "matches an existing recording" 으로 **차단**됐고, v2·v3a/b/c 는 통과했습니다. 차단을 가른 것은 화성이 아니라 **선율 원리듬 전곡 유지와 모방 성부**였습니다.

1. **원곡 성부를 그대로 겹쳐 쓰지 않습니다.** 주제는 한 성부만 가져옵니다. 모방·카논·원곡 성부 더블링은 금지입니다.
2. **리듬을 바꿉니다.** 음고 윤곽은 살리되 다음 중 둘 이상을 씁니다: ① 부분 당김 ② 음가 2배/반 ③ 빠른 런을 골격음만 남기기 ④ 스윙이나 셔플 같은 박 분할 변경. 원리듬 그대로인 구간은 **연속 4마디 이하**로 둡니다.
3. **박자나 템포를 옮깁니다.** 원본 BPM 대비 ±15% 이상 바꾸거나 하프/더블타임으로 갑니다. 3/8·12/8 악장은 박자도 다른 박자로 다시 묶습니다.
4. **원곡 베이스 라인을 그대로 깔지 않습니다.** 화성은 새로 짭니다. 조옮김도 허용합니다.
5. **주제는 전체의 40~60% 입니다.** 나머지는 자작 소재(모티프, 전주·간주·후주, 전개)로 채웁니다. 듣는 사람이 "아, 사계"를 알아채되 Suno 필터는 지나가는 지점이 목표입니다.
6. 업로드가 차단되면 ② 리듬 변형 비율을 높이고 ⑤ 주제 비율을 낮춘 다음 판을 만듭니다. 차단과 통과 결과는 반드시 기록합니다.
7. **"matches an existing recording" 반려는 자작 GM 렌더에도 생깁니다**(2026-11-06 lo-fi lh02·lh14, `PROMPT_GUIDELINES.md` §6). support 는 "AI 탐지" 자동 응답만 돌려줘서, 매칭기가 원곡 일치가 아니라 생성물 탐지로 걸 수도 있습니다. 그래서 위 1~5 를 지켜도 반려될 수 있고, 그때는 ⑥ 보다 먼저 템포 메타 ±2 BPM(`-v2u`) 과 드럼 제외 +1 반음 전조(`-v2t`) 를 시험합니다. 반려는 곡별로 달라서 하나가 만능이 아닙니다.

## 3. 장르·편성 (MUST)

- **장르**: 모델이 악장마다 자유롭게 고릅니다. 장르 할당량은 없지만, **12곡이 한두 장르로 모이지 않게** 악장의 성격(템포·박자·표제·질감)에 따라 폭넓게 펼칩니다(사용자 지시 2026-11-09). 이전 라운드가 어떤 장르였는지는 참고하지 않습니다.
- **배제 장르**: 라운드 킥오프의 `배제 장르:` 줄에 적힌 장르만 피합니다. 그 줄이 없거나 비어 있으면 제한이 없습니다.
- **계획 파일**: 작곡 전에 `docs/music/vivaldi_<model>_v2_plan.md` 를 쓰고 자기 브랜치에 커밋합니다. 악장별로 다음을 적습니다.
  - 장르
  - 그 장르를 고른 이유. 원곡 악장의 성격(템포, 박자, 표제, 질감)에서 나온 이유여야 합니다.
  - 편성: 트랙 이름과 PC
  - 박자·BPM·마디 수
- **악기**: `PROMPT_GUIDELINES.md` §4 표(GM 128개 전수)를 기준으로 고릅니다. 비고가 "저품질 GM 폴백"인 번호는 쓰지 않습니다. 비고가 적힌 번호는 GM 이름이 아니라 실제로 로드되는 패치의 소리를 원할 때만 씁니다. §4 의 "GM 번호로는 닿지 않는 패치"(하프시코드, 오보에, 바순, 하프, 팀파니 등)는 패치를 이름으로 불러오는 자동화가 생긴 뒤에만 씁니다.
- **박자**: 4/4 가 아닌 박자는 `pipeline.build_smf(..., timesig=(num, den), tempos=[(tick, bpm), ...])` 로 씁니다(2026-11-09 들여옴, 기본값은 이전 출력과 바이트 동일). 4/4 가 아니면 `bt()`·`BAR` 대신 `bar_ticks = num * PPQ * 4 // den` 로 틱을 직접 계산합니다.
- **길이**: 약 3분입니다(Suno Cover 3분 입력 실측 통과 범위).
- **마커**: 구간 마커를 반드시 넣습니다.
- **점검 줄**: 곡마다 원리듬 최장 연속 마디, 주제 비율, 트랙별 벨로시티 범위, 트랙별 음/마디, 마지막 노트 위치를 출력합니다.
- **밀도**: 숫자 하한은 두지 않습니다. 장르가 자유라서 성긴 실내악 편성도 허용하기 때문입니다. 대신 ① 각 마디에서 울리는 층이 하나뿐인 구간은 전주·후주를 빼고 연속 2마디 이하로 두고, ② 점검 줄에 구간별 음/마디와 베이스 음/마디를 출력하며, ③ v1 청취 판정이 "디테일 부족, 빈 공간 많음"이었음을 알고 씁니다(lo-fi v2 가 보정에 쓴 수단은 `LOFI_HIPHOP_SET_BRIEF.md` `## v2 보정` 에 있고, 계획 커밋 뒤에 참고할 수 있습니다).

### 4.1 라운드 세션 (3층) 운영

- 라운드 세션은 모델당 하나입니다. v1 라운드 워크트리 `band-astra`·`band-fable`·`band-opus`(브랜치 `rae-hugo-kim/band-<model>`, `/Users/hugom4/orca/workspaces/losik/band-<model>`)를 **그대로 재사용**합니다(Orca 부모는 `vivaldi`, 사용자 결정 2026-11-09). 이름이 주제를 보여 주지 않지만 유지합니다.
- **모델 고정(MUST)**: 라운드 세션은 첫 응답에서 세션 설정의 모델 ID 를 적고, 킥오프에 적힌 모델과 다르면 작업을 시작하지 않고 보고합니다. 계획 파일·작곡기 `MODEL` 상수·FEEDBACK_LOG 절 제목·세션 요약에 같은 모델 ID 를 적습니다. 다른 모델의 v1·v2 작곡기 코드를 복제하지 않습니다.
- 라운드 세션은 시작하자마자 `git merge rae-hugo-kim/vivaldi` 로 기준선을 맞춥니다(이 브리프·§4 표·인벤토리·박자 확장이 거기 있습니다). 충돌 규칙: `FEEDBACK_LOG.md`·`SUNO_PROMPTS.md`·`docs/harness/audit.jsonl` 은 양쪽 보존(같은 Vivaldi v1 절이 두 번 나오면 하나만), `PROMPT_GUIDELINES.md`·`tools/pipeline.py`·`docs/harness/verify-commands.json` 은 `rae-hugo-kim/vivaldi` 쪽, 그 밖의 자기 코드는 자기 쪽입니다. 미커밋 잔재(`VIVALDI_KICKOFF.md`, `.omp/mcp.json`)는 건드리지 않습니다.
- 각 라운드 워크트리 루트에 미커밋 `VIVALDI_V2_KICKOFF.md` 를 둡니다. 내용은 모델 ID, 읽는 순서(§0), `배제 장르:` 줄(사용자가 준 목록, 없으면 빈 줄), 산출물(§4), 커밋 대상 브랜치입니다. 인계 문서는 이 브리프입니다.
