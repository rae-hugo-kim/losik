# 다곡 제작 지시문 — 공통 반주 변주가 아닌 독립된 곡 묶음

작성 기준: 2026-09-12. 다음 다곡 배치를 위한 **제안 지시문**이다. 승인된 Astra v3 음악을 다시 바꾸거나, 이 문서를 하네스의 자동 강제 규칙으로 등록한 것은 아니다. 현재 곡의 Suno 투입은 [별도 프롬프트](SUNO_PROMPTS_ASTRA_V3.md)를 따른다.

## 1. 무엇을 바꿔 지시해야 하는가

핵심은 “더 랜덤하게”가 아니라 **공통으로 묶을 것과 독립적으로 결정할 것을 먼저 나누는 것**이다. 여기서 temperature는 창작 폭을 가리키는 비유이며, 모델 API의 temperature 수치를 올리라는 뜻이 아니다.

| 요청 유형 | 고정할 수 있는 것 | 반드시 독립적으로 생각할 것 |
|---|---|---|
| 같은 곡의 A/B 편곡 비교 | 선율·형식·길이·템포 중 비교에 필요한 축 | 비교 대상인 악기·리듬·화성 등 |
| 서로 다른 여러 곡 / 포트폴리오 | 납품 형식, 사용 목적, 넓은 미학적 범위 | 시작, 반복, 감정의 변화, 절정 유무·위치, 주도 악기, 형식, 솔로 필요성, 끝맺음 |

“여러 곡”을 후자라고 명시하면 좋지만, 차이를 끝까지 사용자가 설계해야 한다는 뜻은 아니다. 에이전트가 **작곡 전에 배치 전체의 중복을 발견하고 대안을 만드는 역할**을 맡아야 한다.

## 2. 이번에 비슷해진 이유

첫 제작에서는 “같은 구성”을 같은 100 BPM·4/4·112마디·악기 팔레트·섹션표까지 고정하는 것으로 해석했다. 이후 음색·박자·길이는 달라졌지만, 여전히 “도입 → 벌스/후렴 → 뒤쪽의 특징 구간 → 마지막 고조 → 잔잔한 끝”이라는 익숙한 전개에 끌리는 부분이 남았다.

이번 구현을 보면 단순한 인상만의 문제가 아니다. [v2 형식 정의](tools/tide_v2.py)의 Paper Lanterns와 Northbound Lights는 모두 두 번째 후렴 뒤에 브리지를 두고, 그 뒤에 솔로, 마지막 전개, 아웃트로를 둔다. 실제 v3에서도 특징 구간 시작은 약 2:43과 2:48로 가깝다. 악기와 음표가 달라도 **사건이 일어나는 순서가 같은 것**이다.

참고했던 기존 문서에도 수렴 압력이 있다. [이전 Suno 프롬프트](SUNO_PROMPTS.md)는 여러 곡에 전환부 라이저·임팩트와 마지막 고조를 넣었고, [음악 제작 가이드](PROMPT_GUIDELINES.md)의 경계 처리 기본 세트도 라이저·크래시·필인을 강조한다. 원래는 특정 제작 경험에서 나온 해결책인데, 모든 곡의 음악적 의무처럼 적용하면 온도가 비슷해진다.

따라서 해결책은 사용자에게 형용사를 더 요구하는 것이 아니라, **에이전트가 공용 섹션표를 먼저 복사하지 않는 것**이다. 공용화하기 좋은 것은 파일 생성·악기 로딩·저장·검증 도구이고, 음악의 시간표는 별도로 설계해야 한다.

## 3. 바로 복사할 짧은 지시문

```text
이번에는 같은 곡의 편곡 대안이 아니라, 서로 독립된 여러 곡을 만들어줘.
공통으로 유지할 것은 [사용 목적과 꼭 필요한 조건]뿐이다.
분위기 이름, 코드, 조옮김, 악기 교체만으로 차이를 만들지 말고,
각 곡의 시작 방식, 반복 방식, 리듬의 호흡, 밀도 변화, 감정의 도착점,
절정의 유무와 위치, 주도 악기, 솔로의 필요성과 끝맺음부터 독립적으로 설계해줘.
모든 곡에 도입-상승-후렴-후반 솔로-최종 후렴을 넣지 않아도 된다.
솔로·브리지·라이저는 필요할 때만 쓰고, 넣는다면 왜 필요한지 설명해줘.
먼저 곡별 설계 비교표를 보여줘. 제목과 악기명을 가려도 전개가 비슷한 안은
내가 지적하기 전에 네가 다시 설계해줘. 확인한 뒤 작곡을 시작하자.
```

중간 확인 없이 맡기고 싶다면 마지막 두 문장을 다음으로 바꾼다.

```text
작곡 전에 네가 설계 비교표를 만들고 중복된 안을 스스로 바꾼 뒤 진행해줘.
완료할 때 각 곡이 다른 곡과 구조적으로 무엇이 다른지 짧게 보고해줘.
내 취향에 관한 결정이 꼭 필요할 때만 물어봐.
```

## 4. 사용자가 주면 좋은 최소 입력

전부 채울 필요는 없다. 특히 코드 진행이나 마디 수를 사용자가 직접 정할 필요는 없다.

- **용도:** 감상용 연주곡, 노래 초안, 랩/나레이션 받침, 게임의 특정 장면 등.
- **허용할 온도 범위:** 따뜻함만인지, 서늘함·불안함·장난스러움·거침까지 허용하는지.
- **공통으로 남길 조건:** 예를 들어 “3분 안팎의 인스트”, “실제 밴드로 재연 가능한 편성”. 공통 감정 곡선까지 묶지 않는다.
- **피할 수렴 방향:** “전부 영화 예고편처럼 커지지 않기”, “전부 늦은 밤 감성 피아노로 가지 않기”.
- **곡별 출발 장면이 있다면:** “조심스럽게 걷는다”, “처음부터 달린다”, “말하려다 멈춘다”처럼 행동을 준다. 장면 자체를 효과음으로 만들라는 뜻은 아니다.
- **레퍼런스가 있다면:** 곡 전체가 아니라 가져올 요소와 버릴 요소를 함께 적는다. 같은 한 곡을 모든 항목의 정답으로 두지 않는다.

예: “스틸스트링의 질감은 공통으로 좋아하지만, 전부 따뜻하고 잔잔하게 시작할 필요는 없다. 어떤 곡은 첫 소절부터 훅, 어떤 곡은 끝까지 숨긴 감정이어도 좋다.”

## 5. 에이전트가 작곡 전에 보여줄 설계표

수치를 먼저 채우는 표가 아니라 **선택의 이유를 드러내는 표**다. BPM·조성·마디 수는 아래 음악적 결정을 구현하는 값으로 뒤에 붙인다.

| 축 | 답해야 할 질문 |
|---|---|
| 장면·화자의 태도 | 이 곡은 무엇을 하고 있고, 왜 움직이거나 멈추는가? |
| 첫인상 | 첫 10~20초에 이미 훅이 있는가? 독주인가? 리듬부터인가? 의도적으로 늦게 시작하는가? |
| 시간의 흐름 | 순환, 직진, 파동, 급전환, 정지, 해체 중 무엇이 곡을 움직이는가? |
| 반복의 역할 | 같은 프레이즈가 안도감을 주는가, 집착을 만드는가, 다른 맥락으로 돌아오는가? 후렴이 꼭 필요한가? |
| 리듬·프레이즈 | 박자표뿐 아니라 악센트, 당김, 쉼표, 프레이즈 길이, 화성 변화의 속도가 어떻게 다른가? |
| 주도권 | 선율·리듬·화성·음색 중 무엇이 핵심인가? 구간이 바뀔 때 누가 말하고 누가 물러나는가? |
| 밀도·감정 곡선 | 층을 계속 더하는가, 처음부터 가득한가, 덜어 내는 순간이 절정인가? |
| 절정 | 초반/중반/후반/여러 번/뚜렷한 절정 없음 중 무엇이며, 왜 그런가? 최고음과 최대 음량이 꼭 같은 지점인가? |
| 브리지·솔로 | 실제 역할이 있는가? 없으면 넣지 않는다. 솔로라면 반주와 주도권이 어떻게 달라지는가? |
| 끝맺음·길이 | 잔향, 단호한 종료, 미완의 반복, 짧은 결론 등 무엇이 맞는가? 길이는 그 결론에 도달한 결과인가? |
| 버린 대안 | 이 곡에 익숙한 상승-폭발 구조나 후반 솔로를 넣지 않은 이유는 무엇인가? |

### 비교할 때 이름을 가린다

제목·장르·악기명을 지우고 전개만 읽는다.

- “얇은 시작 → 두 번 반복 → 잠깐 비움 → 주악기 솔로 → 다 같이 크게 → 조용한 끝”이 계속 나오면 아직 구조적 다양성이 부족하다.
- 절정·브리지·솔로가 매번 비슷한 재생 시각이나 곡의 같은 비율에 모이는지도 본다. 2:40을 2:50으로 옮기는 정도는 해결이 아니다.
- ABAB 같은 형식 기호가 같다는 이유만으로 탈락시키지는 않는다. 첫 진입, 프레이즈 길이, 주도권 교대, 밀도와 끝맺음이 실제로 다른지가 중요하다.
- 코드·키·BPM만 달라진 것을 구조적 차이의 근거로 쓰지 않는다.
- 희귀한 박자나 악기를 억지로 하나씩 배정하지 않는다. 차이에 음악적인 이유가 있어야 한다.

## 6. 솔로를 넣는다면 이름이 아니라 기능으로 설계한다

“이곳은 솔로”라는 마커나 더 많은 음표만으로는 솔로가 되지 않는다. 다음 중 필요한 장치를 골라 **누가 주도하는지 들리게** 만든다.

- 반주 밀도나 응답 빈도를 줄이고 주악기의 문장 끝을 들을 공간을 준다.
- 주악기만의 긴 도착음, 질문·응답, 음역 이동, 리듬 대비를 만든다.
- 다른 악기는 계속 같은 코드를 두드리기보다 기다리거나 짧게 대답한다.
- 화려함과 주도권을 구별한다. 단순한 선율도 곡을 이끌면 솔로이고, 속주가 많아도 합주에 묻히면 특징 구간일 뿐이다.
- 솔로가 곡의 논리를 바꾸지 못한다면 생략한다. 모든 곡에 하나씩 배정하지 않는다.

## 7. 다른 구조가 가능한지 보여주는 예시

아래는 다음 배치의 고정 템플릿이 아니라 선택 폭을 보여 주는 예시다. 이 다섯 줄을 매번 순서대로 적용하지 않는다.

| 가능한 곡 | 전개 원리 | 절정·솔로·끝 |
|---|---|---|
| 처음부터 훅을 제시하는 짧은 밴드 곡 | 강한 첫인상 뒤에 밀도를 덜고, 같은 훅을 다른 리듬으로 재해석 | 가장 큰 순간이 초반일 수 있음. 솔로 없이 짧게 종료 |
| 말이 들어갈 공간을 가진 피아노 곡 | 큰 공백과 최소 변화가 긴장을 유지 | 전통적 후렴·절정 없음. 불완전한 여운 |
| 두 악기가 대화하는 느린 곡 | 주고받는 문장이 길어졌다 짧아지며 관계가 변함 | 중반의 단둘만 남는 순간이 정점. 후반은 더 작음 |
| 타악·베이스가 이끄는 거친 곡 | 리듬의 맞물림과 멈춤 자체가 사건 | 멜로디 솔로 대신 짧은 리듬 특징 구간. 단호한 끝 |
| 한 번 지나간 선율이 파편으로 돌아오는 곡 | 반복 후렴 없이 계속 이어지는 형식 | 여러 작은 고조. 새로운 악기보다 기존 소재의 의미 변화로 마무리 |

“다섯 곡은 반드시 다섯 장르”나 “하나는 반드시 7/8”처럼 또 다른 체크리스트를 만드는 것이 목적이 아니다. 같은 장르·같은 악기로도 **시간을 사용하는 방식과 감정의 도착점**이 다르면 충분히 다른 곡이 된다.

## 8. Suno 초안이라는 목적에 맞춘 작업 순서

1. **배치 설계:** 독립된 곡의 목적과 전개를 짧게 비교한다. 비슷한 안은 여기서 바꾼다.
2. **핵심 소재:** 곡마다 다른 주도 요소를 먼저 만든다. 모든 곡을 같은 길이의 리드 모티프부터 시작할 필요는 없다.
3. **필요한 만큼 확장:** 승인한 전개에 맞춰 길이를 정한다. 112마디, 후반 솔로, 마지막 옥타브 상승을 기본값으로 깔지 않는다.
4. **의도가 읽히는 초안:** 악기 관계와 특징 구간이 전달될 만큼만 다듬는다. Suno에 넘기기 전부터 완성 믹스를 만들려고 과도하게 반복하지 않는다.
5. **Suno 결과로 판단:** 실제 완성본의 감정·용도·변화를 듣고 다음 작업을 정한다. 이번 Blue Window처럼 판단을 유보하는 선택도 유효하다.

최종 확인 질문은 **“악기를 바꾼 같은 곡들인가, 서로 다른 이유로 흘러가는 곡들인가?”**다.
